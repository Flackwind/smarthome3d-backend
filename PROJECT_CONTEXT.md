# Smart Home 3D API

Backend independent from Angular frontend. Java 21+, Spring Boot 3.5.16, Maven 3.9.11; no npm modules/frontend sources required. Contract: docs/API.md and OpenAPI.

This repository is shared SmartHome3D/backend/, beside frontend/. These are the original working sources with independent Git, without exported duplicates. Run Maven here.

JDBC persistence: default on-disk H2 at ./data; alternative PostgreSQL-compatible schema through environment settings. Validated schema-v1 JSON projects, atomic revisions/ETags, immutable binary assets/cascading deletion. Multipart import/ZIP backup applied transactionally, copies with new IDs. Project backups exclude credentials/accounts.

Owner created manually on first access, PBKDF2 password, HttpOnly/SameSite session with RAM CSRF/explicit CORS; no default password. Servlet sessions not serialized. After backend restart, owner sign-in restores last home/HA authorization without backup import/repeated HA popup.

HA optional through server-defined SH3D_HA_URL. Since November 5, 2026 the refresh token is encrypted in the owner profile at explicit user request, overriding the former RAM-only constraint. AES-256-GCM, random 12-byte nonce/128-bit tag; server-password PBKDF2-HMAC-SHA256 key, 600,000 iterations/dedicated 32-byte DB salt. Session-only key cleared at logout/expiration; password never persisted, independent login hash. Access token/PKCE verifier remain in RAM. No new dependencies.

WebSocket bridge uses cookie/session key without browser tokens, retaining allowlist/origin checks. Logout closes only that browser’s bridges and preserves owner authorization; explicit HA disconnect deletes credentials, closes all bridges, attempts revocation. Temporary renewal failure preserves connection; 400/401/403 removes it without deleting projects. Different HA URL never receives previous credentials. Profile/salt/encrypted credential excluded from home backups, included only in administrative full-DB backups. Lost/future-changed passwords require re-encryption or HA reauthorization. Details: docs/PROFILE_SECURITY.md.

New owner_profile/owner_ha_connection tables added with CREATE IF NOT EXISTS, without rewriting homes/assets. GET /profile and PUT /profile/active-project retain last home across browsers; deleted IDs are not restored. Earlier RAM-only authorization needs one new HA connection. Tests use no personal data/real HA.

Independent configuration/commands in README.md; tests use temporary databases/fake credentials. Docker/Compose are examples, never started automatically.
